Racing Telemetry System

Java MQTT Gradle JSSC IoT Gateway

Bridge between Car and Clouds

Developed for the MoRe Modena Racing team, this project acts as the "brain" on board the vehicle for real-time data acquisition.

I worked on this together with my colleagues Pietro Carrucciu and Davide Paltrinieri. The goal was to build a reliable gateway that could bridge the gap between the car's physical electronics (CAN bus) and the digital world of real-time dashboards and remote analytics.

How it works

The application runs on a small PC onboard the car. It handles the constant stream of data coming from the engine and sensors, making it available for the rest of the team in the pits.

Real-Time Data Pipeline

The gateway performs a few key tasks every millisecond:

  • CAN-to-Digital: It reads raw frames from the vehicle's CAN bus through a serial/USB interface and decodes them into actual measurements like RPM, temperature, or speed.
  • Digital Twin Sync: The app maintains a dynamic software model (a "digital twin") of the car's current state, which is updated instantly as new data arrives.
  • MQTT Publishing: Using the MQTT protocol, it streams this data to a remote broker, allowing engineers in the pits to monitor the car's health on their dashboards in real-time.

Technical Architecture

To handle the high demands of racing telemetry without lag, we built it with a multithreaded architecture. One thread is dedicated exclusively to high-speed serial reading, while another handles data normalization and cloud synchronization. This ensures that even under heavy load, the car's status is always accurately reflected.

Technical Details

  • Language: Core Java for performance and portability.
  • Build Tool: Gradle for dependency management and automated builds.
  • Connectivity: JSSC (Java Simple Serial Connector) for hardware communication and Paho MQTT for messaging.
  • Data Formats: JSON (Jackson/org.json) and Google Protobuf for efficient data mapping and serialization.
